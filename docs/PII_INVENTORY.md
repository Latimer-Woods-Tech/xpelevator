## Scope

XPElevator is a virtual-customer training simulator. Trainees ("employees") run
simulated customer conversations (chat, browser voice, real phone) and are scored
against weighted per-role criteria. The personal data we hold therefore falls into
two buckets: **who the trainee is** (identity) and **what the trainee did**
(conversation transcripts + performance scores).

Data at rest lives in the org Neon Postgres project `aged-butterfly-52244878`
(XPElevator is on Neon by design — driver rewrite off `neon()` pending before any
OCI cutover). Sessions are stateless JWTs (Auth.js / NextAuth v5, `strategy: jwt`);
**no server-side session records are stored**.

## What we store (at rest — Neon Postgres)

The columns below are the personal-data-bearing fields. Table/column names are the
DB names (`@map`), not the Prisma model names. Non-personal columns (ids, FKs,
timestamps, telemetry) are omitted unless they link a person to activity.

| Table | Column | Data | Category | Notes |
|-------|--------|------|----------|-------|
| `users` | `email` | Login email (unique) | **Direct identifier** | Source: GitHub OAuth email, or the email typed into the Credentials provider. Lower-cased on write. |
| `users` | `name` | Display name (nullable) | Personal data | From GitHub OAuth, or defaulted to the email local-part on credentials auto-create. |
| `users` | `role` | `ADMIN` \| `MEMBER` | Access attribute | Not PII on its own; governs what the person can see. |
| `simulation_sessions` | `user_id` | Auth subject id (NextAuth) | Pseudonymous identifier | The GitHub OAuth subject, or the `users.id` UUID for credentials sign-in. Links a person to a training session. |
| `simulation_sessions` | `db_user_id` | FK → `users.id` | Linkage | Resolves a session to the durable user row when one exists. |
| `chat_messages` | `content` | Full turn text | **Sensitive — free-text transcript** | The trainee's own typed (chat) or speech-to-text'd (voice/phone) words, plus the simulated customer's replies. Free text: may contain whatever the trainee chooses to say. Retained indefinitely today. |
| `scores` | `score` | Numeric /10 per criterion | Performance data | Tied to an identifiable trainee via the session. |
| `scores` | `feedback` | Per-criterion rationale (nullable) | Performance data | Generated by the scoring engine about the trainee's handling of the call. |
| `audit_log` | `actor_email` | Email snapshot of the admin who made a governance change (nullable) | **Direct identifier** | An append-only accountability record (R-078). FK-free by design so the row **outlives** the org/user it describes; retained longer than operational data — see `RETENTION.md`. |

Org rows (`organizations`: `name`, `slug`, white-label branding) are **tenant /
operator business data, not personal data**, and are listed here only so the
boundary is explicit — a public read of branding is deliberately projected to the
four brand-safe fields (`src/lib/branding.ts` / `GET /api/branding/[slug]`).

### Not stored (deliberate — recorded so future changes are visible)

- **Passwords / credential secrets.** There is no password column. The Credentials
  provider performs **no** password verification (email-only; dev/demo, and
  excluded in production unless `AUTH_CREDENTIALS_ENABLED=true`). GitHub OAuth is
  the production path. Nothing password-like is at rest. *(If a future slice adds
  password auth — the `password` field is a placeholder for future bcrypt — this
  line must move up into the table above.)*
- **Phone numbers.** The schema has no phone-number column. Numbers appear only in
  transient Telnyx call setup / `clientState` and inbound webhook payloads; they
  are not persisted to a durable column. The phone path also logs call **metadata
  only, never the transcript text** to application logs (`src/app/api/telnyx/webhook/route.ts`);
  the caller's turns are still saved as `chat_messages.content` rows like any other
  modality.

## Where PII flows (processors / sub-processors)

Third parties that receive personal data in the course of operating the product:

| Processor | Data it receives | Purpose | Status |
|-----------|------------------|---------|--------|
| **Groq** | `chat_messages.content` (transcript turns) | LLM inference for the simulated customer replies + scoring | Active (direct API; org LLM-chain adoption is Phase 5) |
| **Telnyx** | Call audio, phone numbers, STT of the caller's voice | Phone modality (outbound call + inbound webhook) | Active for phone sessions |
| **GitHub** | OAuth identity (email, name) | Production sign-in (Auth.js provider) | Active when OAuth is configured |
| **Cloudflare** | All request/response data in transit; edge + Pages logs | Hosting (OpenNext on Pages) + Hyperdrive DB connection | Active |
| **Neon** | Everything in the "at rest" table above | Primary datastore | Active |
| **Deepgram / ElevenLabs** | Voice audio (STT/TTS) | Voice-quality upgrade | **Planned** (Phase 5) — not yet wired |
| **Sentry / PostHog** | Errors + product analytics events | Observability | **Planned** (issue #154, founder-gated) — not yet wired, so no analytics PII processor is active today |

## Data-subject rights — current state

- **Access / export.** ✅ A **self-service DSR access endpoint ships**:
  `GET /api/me/export` (R-081) lets any authenticated trainee download a JSON copy
  of their **own** identity, own org context, and every session (transcript,
  telemetry, weighted scores), strictly self-scoped, with hidden scenario
  mechanics never included. (Separately, an admin can export completed-session
  scores for their own org via `GET /api/reports/sessions` — a reporting artifact,
  not a subject-access request.)
- **Deletion.** No automated deletion or retention job exists yet. Transcripts,
  scores, and user rows are retained **indefinitely** today. A **proposed**
  retention schedule + DSR-deletion process is drafted in `docs/RETENTION.md`
  (DRAFT, pending founder ratification — enforces nothing).
- **Isolation.** Access is tenant-scoped at the API layer (owner-or-same-org-admin,
  `canAccessSession`); structural RLS is tracked as debt in #157.
